# Mesh Repair для Blender 5.3

Аддон переносит вычислительное ядро
[MeshRepair 1.0.0](https://github.com/modeco46/MeshRepair) в Blender. Отдельные Qt/VTK-интерфейс и окно
предпросмотра удалены: входом служат выбранные объекты сцены, а исправленная сетка появляется новым объектом.
Исходные объекты не изменяются.

Тяжёлые операции по-прежнему выполняет нативный MeshLib:

- CUDA автоматически применяется для winding number и проекций, если доступна совместимая NVIDIA GPU;
- остальные операции используют нативную CPU-многопоточность MeshLib;
- расчёт идёт в отдельном процессе, поэтому Blender остаётся отзывчивым, а кнопка «Остановить» завершает задачу;
- в JSON-отчёте фиксируются фактически выбранные backend, этапы, время и предупреждения.

## Крупные сетки в 1.4.1

Для исходников от миллиона треугольников аддон согласует ориентацию граней, закрывает безопасные
контуры и отправляет оставшиеся повреждения в воксельный ремеш при выбранном шаге. Исправное
замкнутое тело сохраняет собственную поверхность. Команда «Проверить» по-прежнему даёт полную
диагностику исходника. При ремонте достаточно обнаружить первое самопересечение, чтобы выбрать путь.

Для одной закрытой повреждённой оболочки применяется знаковое поле OpenVDB в полосе вокруг поверхности.
На том же шаге выполняется расширение и сжатие на 0,35 вокселя, чтобы устранить микротуннели в
местах самокасания. Аддон проверяет число сквозных отверстий, целостность и расстояния от вершин
обеих поверхностей. Если проверка не проходит, остаются открытые края или несколько пересекающихся
оболочек, используется winding с тем же шагом и автоматической поддержкой CUDA. Настройка
«Восстанавливать острые рёбра» использует свой проверяемый путь.

Если поверхность перед общим упрощением содержит миллион треугольников или больше, сначала
выполняется консервативная децимация с сохранением координат выбранных вершин. После успешного
сокращения минимум вдвое следующие проходы работают на уменьшенной сетке. После отказа первого
прохода предусмотрена одна более осторожная попытка на плотной сетке. Проверки объёма, топологии
и отклонения используют поверхность перед упрощением. Для принятого результата OpenVDB дополнительно
проверяется суммарное отклонение от сетки после закрытия дыр.

## Версия 1.4.0

Ремонт начинается с точной очистки повторов и граней нулевой площади. Для плоской крышки
с опорой на соседние грани используются вершины существующего контура. Копланарные контуры
одного тела можно закрыть вместе, например восстановить торец втулки вокруг её сквозного отверстия.
Площадь и пересечения такой заплатки проверяются до принятия. Плоский исходник без толщины
получает диагностику с подсказкой про Solidify.

Для сборок из 33–128 замкнутых оболочек (до миллиона треугольников) перед вокселями возможен
групповой Union. Он проверяет каждую оболочку, итоговую топологию, объём и расстояния между
оболочками и результатом. Для остальных случаев сохраняются локальный ремонт и воксельный путь 1.1.3.

Общее упрощение и финальные плоскости сохраняют число оболочек и суммарное число сквозных отверстий.
Изменение объёма на этих этапах ограничено 2% относительно тела сразу после ремонта. Выбранный допуск
по расстоянию проверяется отдельно. После трёх отклонённых попыток возможна одна попытка схлопывания
в уже существующие вершины в рамках прежнего лимита поиска. Приоритет отдаётся сохранению формы.

Blender получает проверенные координаты и индексы треугольников напрямую. В процессе работы панель
показывает этап и прошедшее время. После кнопки «Остановить» для проверки и ремонта можно сохранить
JSON с последним этапом, сообщением, допуском и временем. На результатах крупнее 250 тысяч треугольников
статистика распределения плоскостей помечается как выборочная. Геометрические проверки выполняются
на полной модели.

Реализация и параметры сверялись с фильтрами
[Close Holes и Quadric Edge Collapse в MeshLab 2025.07](https://github.com/cnr-isti-vclab/meshlab/blob/dc48b91ae562756a6988048c5d5c7f1d2b687256/src/meshlabplugins/filter_meshing/meshfilter.cpp#L1488)
и [фильтрами очистки](https://github.com/cnr-isti-vclab/meshlab/blob/dc48b91ae562756a6988048c5d5c7f1d2b687256/src/meshlabplugins/filter_clean/cleanfilter.cpp#L537).
MeshLab использовался для сравнения. Аддон выполняет ремонт средствами MeshLib.

## Установка

1. Скачайте ZIP **windows-x64** из Releases. Не берите `Source code.zip`: в нём нет нативных зависимостей.
2. В Blender 5.3 откройте `Edit → Preferences → Extensions → Install from Disk…` и выберите ZIP целиком.
3. В 3D View откройте боковую панель клавишей `N`, затем вкладку **Mesh Repair**.

Windows-сборке не нужны отдельно установленные Python, CUDA Toolkit или Visual Studio. Для CUDA нужен только
совместимый драйвер NVIDIA. Если GPU недоступна или выделение VRAM не удалось, ядро автоматически продолжает на
CPU и записывает причину в отчёт. Флаг «Без CUDA» принудительно выбирает CPU.

## Использование

1. Выберите один или несколько mesh-объектов. Модификаторы и Geometry Nodes вычисляются перед передачей ядру.
2. Единицы берутся из `Scene → Units → Unit Scale` и переводятся в миллиметры автоматически. Например,
   `Unit Scale = 0.001` означает 1 BU = 1 мм. Аддон не меняет масштаб сцены и не показывает выбор единиц.
3. Задайте допуск 0,001–0,5 мм (по умолчанию **0,02 мм**) и нажмите «Проверить» или «Исправить выбранное».
4. После ремонта аддон создаёт `<имя>_repaired` в текущей коллекции, делает его активным и задаёт **Flat Shade**.
   Материалы, UV и другие
   негеометрические данные намеренно не переносятся: результат — проверенная треугольная поверхность.

«Проверить» выполняет полную диагностику без изменения сцены. «Сохранить JSON-отчёт» сохраняет технический отчёт;
его копия также остаётся в Blender Text Data Block. Геометрию можно сохранять в `.blend` либо экспортировать
стандартными средствами Blender.
При ошибке сохраняется отчёт именно неудачного запуска: допуск, завершённые этапы, причины отклонения
локальных исправлений, последние сообщения и traceback. Предыдущий успешный отчёт не выдаётся за текущий.

Панель: «Проверить» → краткая информация → допуск → крупная кнопка «Исправить выбранное».
Все остальные параметры и сохранение отчёта находятся внутри свёрнутых «Расширенных настроек».
По умолчанию включены схлопывание плоскостей, общее упрощение, склейка близких вершин, удаление оболочек < 50 граней
и скрытие исходников. Восстановление острых рёбер, строгое доказательство допуска и «Без CUDA» выключены.
Явно сохранённые настройки существующего `.blend` не перезаписываются при обновлении.

«Схлопывать плоскости» выполняет дополнительный финальный проход, в том числе при включённом общем упрощении.
Он удаляет лишние копланарные треугольники, сохраняя углы и границы. Итог проверяется относительно сетки до
упрощения: допуски разных проходов не складываются. Параметр угла доступен в расширенных настройках.

«Посмотреть отклонения» окрашивает исправленную модель в Solid-режиме: синий — 0 мм, зелёный — допуск,
красный — 2 допуска и больше. Легенда и максимум показаны под кнопкой. «Скрыть отклонения» восстанавливает
предыдущее освещение и режим отображения. Материалы модели не меняются.

Карта вычисляется по запросу отдельным worker с CUDA/CPU fallback и показывает расстояние **вершин результата
до треугольников исходника**, с интерполяцией цвета внутри граней. Это измерение в вершинах, а не доказательство
границы для всей поверхности. Статистика `source_deviation` в отчёте относится к обратному направлению и может
отличаться. Сначала создайте карту до редактирования результата или следующего ремонта: исходная геометрия
хранится во временном задании. Построенная карта хранится в атрибутах объекта и сохраняется вместе с `.blend`;
после открытия файла выберите объект и нажмите «Посмотреть отклонения». После ручного редактирования карта
остаётся снимком исходного ремонта; для нового измерения выполните ремонт заново.

## Мелкий допуск и время расчёта

Допуск также определяет шаг воксельного восстановления. Число ячеек объёма растёт примерно как `1 / шаг³`,
число треугольников поверхности — как `1 / шаг²`. При переходе с 0,02 на 0,015 мм это примерно ×2,37 и ×1,78
соответственно. Время всего ремонта также зависит от дыр, пересечений, проверки и попыток упрощения;
время вокселизации не является временем всего задания. CUDA ускоряет winding и проекции, а проверки топологии
и упрощение выполняются на CPU.

Большие сетки считаются по слоям на CPU либо CUDA с поддержкой обработки по частям. Общее число ячеек
не означает одновременное хранение всего объёма, поэтому прежний отказ при 6 млрд ячеек убран.
Промежуточная треугольная поверхность всё равно должна помещаться в RAM. Проба и предупреждения не меняют
выбранный допуск. Сетка с оставшимися пересечениями не принимается как успешно исправленная.

С версии 1.1.3 локальный ремонт сохраняет промежуточные улучшения и обрабатывает оставшиеся пересечения.
Проверка расстояния после изменения связности проецирует изменённые участки; неизменённые грани исключаются
по точному совпадению координат и индексов. Общие проверки топологии и пересечений сохраняются.
Полный повтор с winding beta 4 по умолчанию отключён: callback не может прервать уже выполняющееся
CUDA-вычисление, поэтому такой повтор мог занимать много минут сверх заявленного лимита.

## Сохранённая функциональность MeshRepair

- согласование нормалей, точная склейка совпадающих вершин и необязательная склейка близких;
- заполнение простых дыр, локальный CutAndFill и проверка самопересечений;
- точное объединение пересекающихся замкнутых оболочек без вокселей, когда это безопасно;
- OpenVDB/winding-реконструкция сложных дефектов, оценка размера сетки и времени до полного прохода;
- восстановление острых рёбер и управляемый повтор без Sharpening;
- удаление внутренних полостей/нулевой толщины и необязательное удаление оболочек меньше 50 граней;
- плоское и общее QEM-упрощение с измеренным либо строгим допуском;
- проверка записи координат и индексов для Blender, карта отклонений, статистика оболочек и полный JSON-отчёт;
- при отдельном экспорте STL через API ядра — проверка повторной загрузки и отчёт по попыткам экспорта.

Отдельный viewport, Qt/VTK, диалог открытия файлов, темы и desktop-настройки не включены: их функции уже выполняет
Blender. Это уменьшает размер прикладного кода и исключает второй графический стек.

## Сборка из репозитория

Релизная упаковка рассчитана на Blender 5.3 и его Python 3.13:

```bash
python scripts/build_release.py --target windows-x64
```

Скрипт скачивает только бинарные wheels, помещает их в `mesh_repair_blender/vendor` внутри временной сборки и
создаёт самодостаточный ZIP в `dist/`. Бинарники не хранятся в Git. Исходную папку без `vendor` можно использовать
для разработки, задав `MESH_REPAIR_PYTHON` на Python с установленными `meshlib`, `numpy` и `scipy`.

Тесты:

```bash
python -m pip install --only-binary=:all: -r requirements-dev.txt
python -m pytest
python -m ruff check mesh_repair_blender tests scripts
```

Вычислительное ядро основано на commit `6ca780f` исходного MeshRepair с локальными исправлениями; детали находятся в
[UPSTREAM.md](UPSTREAM.md). Условия бинарных зависимостей перечислены в [THIRD_PARTY.md](THIRD_PARTY.md).

## Ограничения платформ

Проверки и публикация выполняются только для Windows x64. ZIP содержит библиотеки для этой платформы.
Работу CUDA и производительность необходимо измерять на целевой NVIDIA
GPU: CI без физической GPU проверяет CPU-путь и наличие CUDA-интерфейса, но не подменяет аппаратный тест.
