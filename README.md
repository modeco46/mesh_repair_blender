# Mesh Repair для Blender 5.3

Аддон переносит вычислительное ядро
[MeshRepair 1.0.0](https://github.com/modeco46/MeshRepair) в Blender. Отдельные Qt/VTK-интерфейс и окно
предпросмотра удалены: входом служат выбранные объекты сцены, а исправленная сетка появляется новым объектом.
Исходные объекты не изменяются.

Тяжёлые операции по-прежнему выполняет нативный MeshLib:

- CUDA автоматически применяется для winding number и проекций, если доступна совместимая NVIDIA GPU;
- остальные операции используют нативную CPU-многопоточность MeshLib;
- расчёт идёт в отдельном процессе, поэтому Blender остаётся отзывчивым, а кнопка «Остановить» завершает задачу;
- в JSON-отчёте фиксируются фактически выбранные backend, этапы, время и предупреждения.

## Установка

1. Скачайте ZIP **для своей ОС** из Releases. Не берите `Source code.zip`: в нём нет нативных зависимостей.
2. В Blender 5.3 откройте `Edit → Preferences → Extensions → Install from Disk…` и выберите ZIP целиком.
3. В 3D View откройте боковую панель клавишей `N`, затем вкладку **Mesh Repair**.

Windows-сборке не нужны отдельно установленные Python, CUDA Toolkit или Visual Studio. Для CUDA нужен только
совместимый драйвер NVIDIA. Если GPU недоступна или выделение VRAM не удалось, ядро автоматически продолжает на
CPU и записывает причину в отчёт. Флаг «Без CUDA» принудительно выбирает CPU.

## Использование

1. Выберите один или несколько mesh-объектов. Модификаторы и Geometry Nodes вычисляются перед передачей ядру.
2. Выберите единицы. По умолчанию `1 BU = 1 мм`, что соответствует исходному MeshRepair и типичному STL для
   ювелирных моделей. «Единицы сцены» использует `Scene → Units → Unit Scale`; `1 BU = 1 м` доступен явно.
3. Задайте допуск 0,001–0,5 мм и нажмите «Проверить» или «Исправить выбранное».
4. После ремонта аддон создаёт `<имя>_repaired` в текущей коллекции и делает его активным. Материалы, UV и другие
   негеометрические данные намеренно не переносятся: результат — проверенная треугольная поверхность.

«Проверить» выполняет полную диагностику без изменения сцены. «Сохранить JSON-отчёт» сохраняет технический отчёт;
его копия также остаётся в Blender Text Data Block. Геометрию можно сохранять в `.blend` либо экспортировать
стандартными средствами Blender.

## Сохранённая функциональность MeshRepair

- согласование нормалей, точная склейка совпадающих вершин и необязательная склейка близких;
- заполнение простых дыр, локальный CutAndFill и проверка самопересечений;
- точное объединение пересекающихся замкнутых оболочек без вокселей, когда это безопасно;
- OpenVDB/winding-реконструкция сложных дефектов, оценка размера сетки и времени до полного прохода;
- восстановление острых рёбер и управляемый повтор без Sharpening;
- удаление внутренних полостей/нулевой толщины и необязательное удаление оболочек меньше 50 граней;
- плоское и общее QEM-упрощение с измеренным либо строгим допуском;
- проверка итоговой STL round-trip, карта отклонений, статистика оболочек и полный JSON-отчёт.

Отдельный viewport, Qt/VTK, диалог открытия файлов, темы и desktop-настройки не включены: их функции уже выполняет
Blender. Это уменьшает размер прикладного кода и исключает второй графический стек.

## Сборка из репозитория

Релизная упаковка рассчитана на Blender 5.3 и его Python 3.13:

```bash
python scripts/build_release.py --target windows-x64
python scripts/build_release.py --target linux-x64
```

Скрипт скачивает только бинарные wheels, помещает их в `mesh_repair_blender/vendor` внутри временной сборки и
создаёт самодостаточный ZIP в `dist/`. Бинарники не хранятся в Git. Исходную папку без `vendor` можно использовать
для разработки, задав `MESH_REPAIR_PYTHON` на Python с установленными `meshlib`, `numpy` и `scipy`.

Тесты:

```bash
python -m pip install --only-binary=:all: -r requirements-dev.txt
python -m pytest
python -m ruff check mesh_repair_blender tests scripts
```

Вычислительное ядро зафиксировано на commit `6ca780f` исходного MeshRepair; детали обновления находятся в
[UPSTREAM.md](UPSTREAM.md). Условия бинарных зависимостей перечислены в [THIRD_PARTY.md](THIRD_PARTY.md).

## Ограничения платформ

Готовые workflow сейчас собирают Windows x64 и Linux x64. Архивы платформозависимы из-за MeshLib/SciPy; один ZIP
нельзя переносить между Windows и Linux. Работу CUDA и производительность необходимо измерять на целевой NVIDIA
GPU: CI без физической GPU проверяет CPU-путь и наличие CUDA-интерфейса, но не подменяет аппаратный тест.
