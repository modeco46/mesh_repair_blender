# Проверка рекомендаций для тестовой 1.2.0

Ветка: `experimental/1.2.0`. База: `v1.1.3`, commit `19f6839`.
Основная ветка и стабильный релиз не обновляются до сравнения пользователем.
Все публикуемые сборки и проверки Blender в CI рассчитаны на Windows x64 / Blender 5.3.

## Что подтвердилось в коде и логах

В отчётах архангела и иконы после вокселей получены 12,8 и 17,7 млн граней. Упрощение полностью отклонено.
Постоянный максимум 0,0560829 мм у архангела действительно делает повторный глобальный поиск масштаба
малополезным. Однако «иглы/плёнки» пока остаются гипотезой: исходных моделей для воспроизведения нет.

В иконе корректная в памяти сетка не проходит повторную загрузку STL. Старый отчёт не сохранил диагностику
неудачных загрузок, поэтому точный дефект неизвестен. В коде обнаружена ненужная для Blender цепочка
«native mesh → STL → native mesh → массивы». STL не хранит индексы общей сетки: восстановление связности
может иначе обработать совпадающие вершины. В 1.2.0 эта цепочка заменена проверенными массивами координат
и индексов. Точное совпадение после чтения проверяется до передачи в Blender. Это сохраняет валидную сетку,
а не разрешает импорт геометрии с известными пересечениями. Отдельный CLI-экспорт STL по-прежнему проверяется;
`export_attempts` сохраняет диагностику каждого неудачного прохода.

Обход `RegionId` через генератор Python действительно дорог. В 1.2.0 используется пакетное копирование
native int32 с проверкой размера элемента и контрольных значений; при неизвестном ABI есть резервный
публичный итератор. Удаление мелких оболочек использует native regions, их `count()` и одну компакцию.
Для одной оставшейся оболочки её bbox вычисляется нативно без перебора углов всех треугольников.

Тайминг «Проверка восстановленной сетки» из старого отчёта нельзя целиком приписать поиску самопересечений.
Он измерял интервал до следующей смены стадии и включал обработку оболочек и подготовку упрощения;
диагностика реконструкции уже была вычислена и повторно использовалась. Подготовка 18–41 с также включала
Python-перенос идентификаторов компонент, а не только построение структуры проекций. Названия стадий уточнены.

Одинаковое `max_deviation_mm` у упрощения и финальных плоскостей не является кешем: код заново измеряет
расстояние. Максимум может оставаться на не затронутом финальным проходом участке.

## Реализованные изменения

| Область | Поведение 1.2.0 |
| --- | --- |
| Передача результата | Координаты и индексы с точной проверкой записи/чтения; без промежуточного STL |
| Превышение бюджета QEM | Координаты вершин в обоих направлениях, защита ближайших граней и двух колец, до двух повторов |
| Переиндексация защиты | Перенос через `PackMapping.v`; при замене принятой сетки область проецируется заново |
| Постоянный максимум | После защитных повторов одинаковое измеренное превышение останавливает поиск |
| Принятые кандидаты | Следующее упрощение начинается с принятой сетки; опорой допуска остаётся исходная восстановленная поверхность |
| Остаточные пересечения | До 64 пересекающихся граней: ограниченная лестница ремонта, затем полная проверка и общий бюджет |
| Поиск масштаба | Пересечения не меняют верхнюю границу расстояния как будто они монотонны; исследуется другой масштаб |
| Ремонт перед Union | Порог по уникальным внутриоболочечным пересекающимся граням; межоболочечные пары не расходуют этот порог |
| Финальные плоскости | Более 2 млн граней: нативное разбиение на части; небольшие сетки — без швов разбиения |
| Предварительная оценка плоскостей | Эвристика ошибки схлопывания на текущей сетке до 1 млн граней; меньше 3% — пропуск; есть принудительный запуск |
| Статистика плоскостей | До 250 тыс. равномерно выбранных граней, числа явно помечены как оценки; остаточный шум исходника на выборке не вычисляется |
| Удалённая геометрия | Общий `removed_geometry` со стадией, причиной и bbox; мелкие оболочки из ранней очистки также в `removed_shells` |
| Отклонение у удалённых оболочек | Отдельная статистика близости к bbox; эти вершины не исключаются из общего максимума по неподтверждённому предположению |
| Большой результат | Предупреждение при прогнозе более 5 млн граней до полного прохода; размер остаётся видимым в панели |
| Упрощение не принято | Проверенный результат сохраняется, статус `repaired_without_simplification` и предупреждение с числом граней |

Порог локального ремонта перед Union — `max(200, floor(0.001 × число граней))`, применяется именно к
уникальным внутренним пересекающимся граням, а не к числу пар. Сами оболочки проверяются после ремонта,
затем проверяется объединение. Кооперативный бюджет — 15 с для ремонта оболочек и 5 с для ремонта
упрощённого кандидата. Эти пределы проверяются между нативными операциями и не обещают остановить
один длительный native вызов ровно в указанную секунду. «Остановить» в Blender завершает worker-процесс.

Бюджет измеренного упрощения — `0.95q`, всегда относительно сетки до всех проходов. Защита выбирает
вершины с расстоянием больше `0.9 × 0.95q` и сохраняет в отчёте до 20 худших координат; число точек
защиты за один анализ ограничено 50 тысячами. Строгий режим дополнительно доказывает расстояние всей
поверхности в пределах `q`. Исправление исходных дефектов и воксельное восстановление не получают
такой гарантии автоматически: шаг вокселя и расстояние до повреждённого исходника — разные величины.

## Что сознательно не перенесено

- Автоматическое принятие сетки с отклонением до `2q`: это меняло бы заданный бюджет. Неудача упрощения
  получает явный статус; предупреждение об отклонении исходных вершин теперь начинается с `q`.
- Отключение плоскостей по `rougher_than_tolerance` исходника: шум исходника не доказывает отсутствие
  полезных схлопываний в текущей сетке. Большие сетки вообще не пропускают проход по эвристике.
- Замена полной проверки самопересечений инкрементальной: нет доказательства локальности всех изменений
  нативного CutAndFill/дециматора. Полные проверки сохранены; 41 с старого интервала не были временем одной проверки.
- Новая CUDA-вокселизация только в узкой полосе: это отдельный алгоритм извлечения поверхности с обработкой
  знака и границ полосы, а не переключатель текущего вызова. Выигрыш ×20 по этим логам не подтверждён.
  Существующие CUDA и CPU-пути сохранены. CPU-путь можно сравнить флагом «Без CUDA» на той же модели.
- Произвольное уменьшение оценки времени в 1,7–2 раза: двух моделей мало для универсальной поправки.
  Оценка отмечена как эвристика; фактическое время полного прохода и отношение к оценке записываются отдельно.

## Измеренные проверки

Скрипт `scripts/benchmark_performance.py` сравнивает текущий код с отдельным checkout 1.1.3 через
`--package-root`. Ниже один прогон синтетических CPU-сеток в одной среде. Это не замер RTX 3090 и не прогноз
времени архангела или иконы.

| Операция | 1.1.3 | 1.2.0 | Результат |
| --- | ---: | ---: | --- |
| Подготовка упрощения, 1 млн граней | 1,085 с | 0,180 с | Одна оболочка, без защищённых мелких частей |
| Статистика оболочки, 1 млн граней | 1,351 с | 0,099 с | Те же количество, размер и замкнутость |
| Финальные плоскости UV-сферы, 204 800 граней | 0,493 с | 0,578 с | Обе версии: 186 526 граней; здесь предварительная оценка добавляет время |
| Повреждённая сфера, пересекающая вторую сферу | 0,064 с | 0,042 с | В 1.1.3 воксели; в 1.2.0 ремонт оболочки + Union; обе сетки проверены, геометрия различается |

Отдельный нативный тест финальных плоскостей на четырёх CPU: подразделённый куб **2 100 012 → 158 граней
за 6,03 с**. Объём остался 1 мм³, одна замкнутая оболочка, ноль пересекающихся граней. Оставшиеся 158,
а не 12 треугольников — ожидаемая цена защиты швов параллельного разбиения. Сравнения времени этого теста
с 1.1.3 не проводилось.

Регрессии проверяют точность переноса native labels, склейку/ориентацию, защиту вершин после упаковки,
неизменный общий бюджет, сохранение исправленного промежуточного кандидата, прекращение поиска на плато,
Union после ремонта оболочки, ремонт финальных плоскостей, отказ при превышении бюджета, отчёт неудачного
STL, сохранение совпадающих, но разных вершин в массивах, и пометки выборочной статистики.
Windows CI дополнительно запускает Blender 5.3, реальный worker и импорт, включая две оболочки с общей
координатой вершины, Flat Shade, обновление панели по таймеру и карту отклонений.

Для пользовательского сравнения: перезапустить Blender после установки ZIP, выбрать те же **исходные**
объекты и те же настройки. JSON должен содержать `engine_revision: blender-1.2.0` и версию аддона `1.2.0`.
Сохранять отдельные отчёты для каждого допуска; выбор уже исправленного объекта меняет вход задачи.
